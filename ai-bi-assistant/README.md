# Mini AI Business Intelligence Assistant

A small local application for asking natural-language questions about sales transactions. FastAPI serves analytics endpoints, SQLite stores the supplied CSV, and Streamlit provides the dashboard. An optional LLM interprets questions into a small validated intent schema; a deterministic rule-based parser works without an API key. All figures are calculated from database queries, not generated by the LLM.

## Features

- CSV ingestion with data-quality flags and duplicate-import protection.
- SQLite database and parameterized analytics queries.
- FastAPI endpoints for health, summary, monthly revenue, top products, regional revenue, and natural-language questions.
- Streamlit KPI dashboard, monthly chart, regional chart, top products, and question interface.
- Rule-based fallback when the optional LLM is unavailable.
- Pytest tests for ingestion, analytics, parser safety, and API behavior.

## Requirements

Python 3.10+ recommended. Internet access is needed only to install dependencies and optionally call the LLM API.

## Setup on Windows

Open PowerShell in this project folder (`ai-bi-assistant`):

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, use Command Prompt and run:

```bat
.venv\Scripts\activate.bat
```

The supplied source dataset is included at `data/sales_data.csv`. To use a different copy, put it at that path or provide `--csv path\to\your.csv`.

## Import data

Run from the project root:

```powershell
python -m app.ingestion
```

The default SQLite file is `data/sales.db`. Re-running ingestion is safe: transaction IDs are unique and duplicate imports are ignored. The ingestion command prints a report with row counts and data-quality flags.

## Run the application

Open **Terminal 1** from the project root:

```powershell
uvicorn app.main:app --reload
```

Open **Terminal 2** from the project root, activate the same environment, and run:

```powershell
streamlit run frontend/dashboard.py
```

Open the Streamlit URL printed in the terminal (normally `http://localhost:8501`). FastAPI documentation is available at `http://127.0.0.1:8000/docs`.

## Optional LLM configuration

The project works without an API key. In PowerShell, configure an API key for the current terminal session if you want LLM-assisted interpretation:

```powershell
$env:OPENAI_API_KEY="your-key-here"
$env:OPENAI_MODEL="gpt-4o-mini"
```

Do not commit API keys. `.env.example` documents the supported variables; copy it to `.env` only if you add local dotenv loading, and keep `.env` out of Git. The current code reads environment variables directly. If the LLM call fails, the application falls back to rule-based parsing.

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Health check |
| GET | `/data/summary` | Row and data-quality summary |
| POST | `/ask` | Natural-language analytics |

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/ask -ContentType 'application/json' -Body '{"question":"What is the total revenue?"}'
```

## Dataset and calculation policy

The source CSV has 51 transaction rows and 10 columns: transaction ID, order date, product, category, region, sales channel, quantity, unit price, discount amount, and status.

- Gross sales = `quantity × unit_price`.
- Net sales = `quantity × unit_price − discount_amount`.
- Default sales KPIs include only `Completed` rows with known, non-negative unit price, quantity, and discount.
- Returned rows are retained for audit and return counts but excluded from sales performance metrics.
- Rows with missing unit prices are retained and flagged, but excluded from revenue metrics. Prices are not imputed.
- Zero-quantity rows are retained and flagged; they contribute zero gross sales.
- Duplicate transaction IDs are ignored during ingestion due to the primary key.

These are explicit project policies. Validate them with the evaluator if a different business definition of revenue is expected.

## Database design

`transactions` stores the original transaction fields plus `data_quality_flags`. `transaction_id` is the primary key. `ingestion_runs` records each import attempt, its source filename, rows seen, inserted, and flagged. SQLite is suitable for this small local challenge and requires no separate database server.

## Testing

From the project root, after installing dependencies:

```powershell
pytest -q
```

Tests use temporary databases for data and analytics tests. API tests should also be run after importing the supplied CSV into the default database. See `tests/` for individual cases.

## Security and reliability

- The LLM never returns executable SQL; it returns an intent JSON object.
- Analytical operations use predefined SQL and bound parameters.
- Supported intents are allowlisted and parser rejects obvious destructive-query instructions.
- No database write operation is exposed through the question endpoint.
- Do not commit `.env`, API keys, or the generated SQLite database.

## Known limitations

- The rule-based parser supports a finite set of question patterns and month formats. Rephrase unsupported questions.
- The optional LLM interpreter is configured for OpenAI-compatible chat completions and requires a valid key/model.
- The LLM output is schema-checked, but month validation should be strengthened if the app is expanded beyond the supplied dataset.
- This is a local demonstration app, not a production multi-user service. Authentication, rate limiting, audit logging, and deployment hardening are out of scope.
- Returned transaction amounts are not subtracted from completed sales; returned rows are excluded. This is a deliberate reporting policy, not a full accounting ledger.
